## شمارش ارجاع

روشی که تعداد ارجاع را برای آدرس حافظهٔ یک متغیر مشخص بازمی‌گرداند:


```python
import ctypes

def ref_count(address):
    return ctypes.c_long.from_address(address).value
```

بیایید یک متغیر بسازیم و تعداد ارجاع آن را بررسی کنیم:


```python
my_var = [1, 2, 3, 4]
ref_count(id(my_var))
```




    1



تابع داخلی دیگری نیز وجود دارد که می‌توانیم برای به‌دست آوردن تعداد ارجاع از آن استفاده کنیم:


```python
import sys
sys.getrefcount(my_var)
```




    2



اما چرا این تابع 2 را بازمی‌گرداند، به‌جای 1 مورد انتظاری که با تابع قبلی به‌دست آوردیم؟

پاسخ: تابع *sys.getrefcount()* متغیر **my_var** را به‌عنوان آرگومان دریافت می‌کند، این بدان معناست که **همچنین** یک ارجاع به آدرس حافظهٔ **my_var** دریافت (و ذخیره) می‌کند — از این رو شمارش یک واحد بیشتر است. بنابراین ما به‌جای آن از *from_address()* استفاده خواهیم کرد.

ما یک ارجاع دیگر به **همان** ارجاع `my_var` ایجاد می‌کنیم:


```python
other_var = my_var
```

بیایید به آدرس حافظهٔ آن دو متغیر و تعداد ارجاع‌ها نگاه کنیم:


```python
print(hex(id(my_var)), hex(id(other_var)))
print(ref_count(id(my_var)))
```

    0x1e43f368388 0x1e43f368388
    2


یک ارجاع را به‌زور حذف می‌کنیم:


```python
other_var = None
```

و دوباره به تعداد ارجاع نگاه می‌کنیم:


```python
print(ref_count(id(my_var)))
```

    1


می‌بینیم که تعداد ارجاع به 1 بازگشته است.

احتمالاً هرگز نیازی به انجام چنین کاری در پایتون نخواهید داشت. مدیریت حافظه کاملاً شفاف است — این فقط برای نشان دادن بخشی از آنچه در پشت صحنه اتفاق می‌افتد است، زیرا به درک مفاهیم پیش‌رو کمک می‌کند.
